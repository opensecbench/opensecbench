# OpenSecBench design docs

Architecture Decision Records (ADRs) and open-format specifications. Per our working agreement,
**a short design doc lands here before its subsystem is built**, and docs are kept current as
decisions change. The authoritative product/roadmap plan lives outside the repo (planning
scratch); these docs are the buildable, versioned foundation.

| [0028](adr-0028-disposition-routing.md) | Post-run disposition routing + investigations | Accepted — delivered. Tool-declared disposition rules (`pkg/disposition`, manifest + project overrides) route interpreted observations after a run: auto-**finding**, tracked **investigation** (human-triggered vuln-validator thread, human-gated), or **review**. Observations gain structured `attributes`; TruffleHog ships verified→finding, unverified→investigate |
| [0029](adr-0029-observation-dedup-multitool-routing.md) | Observation dedup + multi-tool routing | Accepted — delivered. Observations gain a content **fingerprint** so a re-scan doesn't re-create or re-dispose a known finding (no duplicate observations / repeated investigations / token spend). The SARIF interpreter now carries `tool`/`security_severity` attributes + CVSS-refined severity; **semgrep** & **grype** declare high/critical→investigate. Foundation for ADR-0030 reachability |
| [0030](adr-0030-reachability-exposure.md) | Static reachability + exposed-service model | Accepted — Phase 1 delivered. Real Go call-graph reachability (**govulncheck** capability + interpreter → `reachable` attribute) + a derived **exposed-service** signal (`ProjectExposure`; engine enriches `exposed` on observations); routes `reachable + exposed → investigate`, keeping imported-but-uncalled / internal-only vulns out of triage. SAST reachability + grype/SBOM correlation are Phase 2 |
| [0031](adr-0031-cross-tool-reachability.md) | Cross-tool reachability correlation | Accepted — Phase 2a delivered. Reachability verdicts are stored per **CVE** (`reachability` table; `SetReachability`/`ReachabilityForCVE`), populated by any analyzer (govulncheck) and reused to enrich other tools' CVE findings. **grype** now gates on it: `reachable:false → review` (downgrade even if high), `reachable+exposed → investigate`, else severity fallback. Run-order-sensitive; SAST reachability + retroactive re-eval are Phase 2b |
| [0032](adr-0032-sast-dataflow-reachability.md) | SAST dataflow reachability | Accepted — delivered. A semgrep **taint** finding carries a SARIF `codeFlows` trace (source → sink); the interpreter reads it as `reachable=true` + `dataflow_source`. **semgrep** now routes `reachable+exposed → investigate` (at any severity) with a high-severity fallback — the SAST analog of govulncheck reachability, free from semgrep's own taint engine. Entry-point/route resolution is future work |
| [0033](adr-0033-exposed-routes.md) | Exposed route inventory + route-aware findings | Accepted — delivered. A `routes` table + `route-map` capability (bundled offline semgrep ruleset) extracts declared HTTP routes; `ReconcileObservedRoutes` confirms them against captured traffic (and records traffic-only routes when there's no source). A finding whose handler file declares an exposed route gets an `exposed_route` attribute + 🌐 pill — refining project-level `exposed` to a specific entry point. File-level proximity; degrades gracefully with partial info |
| [0034](adr-0034-route-confirmed-escalation.md) | Route-confirmed escalation | Accepted — delivered. Makes `route_observed` a routing **gate**: a finding in a traffic-confirmed exposed route's handler escalates to investigate at medium+, even without a reachability proof. Escalate-only (never downgrades on a missing route — detection is incomplete); grype's authoritative `reachable:false` still wins |
| [0035](adr-0035-autonomous-assessment.md) | Signal-aware autonomous assessment | Accepted — delivered. The Analyst drives a full source assessment (recon → scan → signal-aware triage → validate → draft report) as a bounded run that **proposes** for human confirmation. New `list_observations`/`list_investigations` tools expose the routing attributes; the investigation seed carries them (`describeSignals`); an `assessor` profile (no `create_finding`) + an `assessment` playbook keep findings human-gated by construction |
| [0036](adr-0036-sast-engines.md) | Pluggable SAST engines | Accepted — opengrep default + Semgrep-Pro delivered; Checkmarx planned. **opengrep** (LGPL Semgrep fork, `osb/opengrep` image) is the default SAST engine — `--dataflow-traces` emits the SARIF `codeFlows` that Semgrep CE masks, so reachability (ADR-0032) works free (validated in Docker). **Semgrep** stays for existing licenses (`pro=true` + `SEMGREP_APP_TOKEN`); **Checkmarx** planned (licensed). All share the SARIF pipeline |
| [0037](adr-0037-dedup-polish.md) | Observation & investigation dedup polish | Accepted — delivered (from live E2E testing). `GET /v1/projects/{id}/observations`; **refresh-on-rescan** (a deduped observation's severity/attributes update without re-firing dispositions or disturbing triage); **cross-tool vuln dedup** (`investigation_vulns` — the same CVE from grype (GHSA) + govulncheck (CVE) opens one investigation, not two) |
| [0038](adr-0038-tech-scout.md) | Tech-scout research agent | Accepted — delivered. An Analyst agent that identifies the stack (`list_dependencies`), researches it from trusted web sources (`web_fetch`, gated by a **preapproved-source** allowlist — auto on NVD/OSV/GHSA/MITRE/OWASP/CIS, approval otherwise), and drafts gotchas/hardening into the KB + corpus (`save_context`, RAG precursor). Fetched content is treated as untrusted. `tech-scout` profile + playbook. Preapproved sources sidestep the playbook-can't-pause problem |
| [0039](adr-0039-rag-index.md) | RAG index over the corpus | Accepted — delivered. Semantic retrieval over the corpus + KB: chunk + embed + store vectors (`corpus_chunks`, BLOB + **brute-force cosine in Go** — modernc SQLite has no vector extension), a `search_corpus` tool (+ `osb rag reindex\|search`). Embeddings default **local** (ollama, `OSB_EMBED_*`) so the corpus stays on-host; retrieval egress-gated like `read_context`. Index-on-write + reindex |
| [0040](adr-0040-knowledge-capture-loop.md) | Knowledge capture loop | Accepted — delivered. Turns discoveries into durable knowledge: a `knowledge-scribe` profile distills analysis/observations/corpus into KB drafts (architecture/auth/tech_stack/data_flow/conventions/gotchas), a `list_kb` tool to see + dedupe existing knowledge, and a capture step in the playbooks (`capture-knowledge` + onboarding). Drafts stay human-confirmed and carry across engagements. Closes the compile-as-you-discover gap (org/group scope + dossier + freshness are follow-ons) |
| [0041](adr-0041-kb-org-scope.md) | Org/team-level knowledge scope | Accepted — delivered. KB entries can anchor above a target — to an **organization** (or group/global) — and a project **inherits** target + group + org + global (most-specific first). Migration 0043 recreates `kb_entries` with nullable target/group/org anchors + a scope CHECK; `draft_kb_entry` gains a `scope` param (resolves the org from the project). So a fact learned once about how a team is set up applies across all their apps + future engagements |
| [0042](adr-0042-knowledge-dossier.md) | Knowledge dossier | Accepted — delivered. A consolidated "what we know about this system" view: `pkg/dossier` deterministically groups the inherited KB by kind into a read-first brief (architecture → stack → auth → deploy → data flows → conventions → gotchas), marking inherited/draft entries. A `get_dossier` agent tool, `GET /v1/{targets,projects}/{id}/dossier` (+`?format=markdown`), and `osb dossier`. No model call — always available |

## Conventions

- One ADR per decision; format: **Context → Decision → Consequences**.
- ADRs are append-only in spirit: supersede rather than silently rewrite; note status changes.
- Format specs (capability manifest, extension package, playbook, project template) are versioned
  JSON Schemas under `spec/` once they stabilize; ADR-0003 defines their shape.
